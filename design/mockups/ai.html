1

What the model decides, and what it cannot

Fothering's code works out the cause of a spike and which lane, if any, may close. An AI model then explains that evidence in the email you read, and confirms the one closure code approved or says unknown. The model never touches your SES account, and only your reply reopens a lane.

2

The interlock between the model and SES

The model gets one evidence record and no tool that changes anything. Code has already decided which lane, if any, may close. Before any SES call, the action function reloads that record, recomputes the verdict and checks the lane map, whatever the model wrote.

3

What the model does, and what it never does

The split is enforced by permissions and code, not by instructions in a prompt.

It does

  • Read one evidence record that detection code built: counts, rates, a verdict per cause, and at most one lane code approved for closure.
  • Write one paragraph in the email you receive, explaining that evidence.
  • Confirm the approved lane by its option id, or say unknown when the evidence does not hold up.

It never

  • Calls SES or holds a tool that changes anything. The action function does, after reloading the record and checking it, and only for sets you listed at deploy.
  • Picks a lane code did not approve. Any other answer counts as unknown.
  • Pauses the whole account. Every Fothering role carries an explicit deny for it.
  • Reads your reply. Code matches its first line against the exact words reopen and keep closed, or close <lane> after an unknown.
  • Sees a recipient address, a subject line, a message header or any other text that came from outside Fothering.

5

Where it can be wrong

The model's part is small on purpose. It can still get that part wrong, and so can the code around it.

Its explanation can be badly worded, or claim more than the evidence shows. What closed, what stays open, the read-back and the words to reply with come from a template over the closure record, so a poor paragraph cannot change them, and the email names the paragraph the agent wrote.

It can say unknown when code approved a lane and a person would have closed it. That is the intended trade: a missed closure costs you a question, a wrong closure costs you a lane of mail.

Detection only sees what SES publishes. A cause that shows only in your own application logs stays invisible, and the result is unknown.
