1

Deploy into your own AWS account

Fothering runs in your account, in eu-central-1, and nowhere else. Read the template before you deploy it: this sheet lists everything it creates, every permission it asks for, and how to take all of it out again.

NOT YETThe template lands before the live runs. Until then this sheet describes what it will do, and the commands below do not exist.

2

Five steps, one template

The deploy is one CDK app. Synthesizing it is free and offline, so you can read the CloudFormation it produces before anything is created.

  1. 1

    Check what you have

    An AWS account with SES in eu-central-1, one verified identity to send the operator email from, Node.js 22, and AWS credentials for that account.

  2. 2

    Read the template

    Produce the CloudFormation template and read its IAM statements against the table below.

    npm run synth
  3. 3

    Deploy with the switch off

    The stack starts in dry run: it reads events and records what it would do, and makes no SES change.

    npm run deploy
  4. 4

    Name the lanes to watch

    Give each configuration set an EventBridge event destination. Fothering only ever acts on the sets you list.

  5. 5

    Turn the switch on

    Only after a dry-run week you are happy with. From then on, a closure is a real SES call.

Never granted

ses:PutAccountSendingAttributes, the call that pauses a whole account. Fothering cannot stop your receipts even if its own logic is wrong.

5

Taking it out

Removal leaves your SES configuration sets exactly as Fothering last left them, so reopen any closed lane first.

  1. Reopen every closed lane from the console, and wait for each read-back to say true.

  2. Delete the stack. The table, memory, bucket and logs go with it.

    npm run destroy

  3. Remove the EventBridge event destinations you added to your configuration sets.
