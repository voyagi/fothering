1

Deploy into your own AWS account

Fothering runs in your account, in eu-central-1, and nowhere else. Read the template before you deploy it: this sheet lists everything it creates, every permission it asks for, and how to take all of it out again.

NOT YETThe template lands before the live runs. Until then this sheet describes what it will do, and the commands below do not exist.

2

Five steps, one template

The deploy is one CDK app. Synthesizing it is free and offline, so you can read the CloudFormation it produces before anything is created.

  1. 1

    Check what you have

    An AWS account with SES in eu-central-1, one verified identity to send the operator email from, Node.js 22, and AWS credentials for that account.

  2. 2

    Name the lanes to watch

    List each configuration set in the lane map with its stream and whether it carries transactional mail, and give it an EventBridge event destination for send, delivery, bounce, complaint, reject and delivery-delay events. The template reads the map, so this comes first.

  3. 3

    Read the template

    Produce the CloudFormation template and read its IAM statements against the table below.

    npm run synth
  4. 4

    Deploy with the switch off

    The stack starts in dry run: it reads and stores events, and records what it would do instead of changing SES, calling the model or sending email.

    npm run deploy
  5. 5

    Turn the switch on

    Only after a dry-run week you are happy with. From then on, a closure is a real SES call.

The agent runtime holds no SES, DynamoDB or S3 action.

Denied on every role

ses:PutAccountSendingAttributes and ses:UpdateAccountSendingEnabled, which pause a whole account, and ses:UpdateConfigurationSetSendingEnabled, which pauses a configuration set and cannot be limited to one set in IAM. An explicit deny holds even if a broader SES policy is attached to a Fothering role later.

What IAM cannot know is which of your sets carries receipts. So a set is not closeable when it carries Fothering's own email, when it carries more than one stream, or when an identity uses it as its default configuration set while transactional mail through that identity names no set, because pausing it would stop that mail too. A transactional lane is never closed on Fothering's own decision: the email proposes it, and only your reply closes it.

5

Taking it out

Removal leaves your SES configuration sets exactly as Fothering last left them, so reopen any closed lane first.

  1. Reopen every closed lane by replying reopen to its email, and wait for each confirmation to report the read-back as true.

  2. Delete the stack. The table, the reply bucket and the log groups go with it.

    npm run destroy

  3. Remove the EventBridge event destinations you added to your configuration sets.
